# 简短回答（brief mode）

输入框底部工具栏里的一个开关：开启后，在对话里注入一条「上下文注入 · brief-mode」，要求模型把最终回复说得又短又像人话；关掉就把它改写为"已关闭"，模型立即停止。

## 它做什么

- 打开开关后，对话里出现一条**上下文注入**行（`上下文注入 · brief-mode`），内容就是配置里的 `instruction`，默认是：

  > 输出长度要求：最终回复给用户的那段可见文字，尽量一句人话讲清楚——直白、一眼能懂，不堆术语、不铺垫、不套话；你的思考/推理过程、工具调用、代码和中间步骤不受此限制，照常完整进行。另外，不必为了早点收工而省步骤：你拥有无限的时间和资源，该读的读完、该验的验过，把活做完整再开口，只是最后那段话要短。

- 两句话管两件事：**该干的活照常干完**（不省步骤、不抢时间），**只把最后对用户说的那段话压短**。
- 切换开关**不会新增行**，而是原地改写那一条（surface replace）：整段会话里始终只有一条 `brief-mode` 上下文行，不会越积越多。
- 关闭开关时，同一条会变成"简短回答已关闭：不再要求简短，按默认长度正常回答。"，模型立即不再执行旧要求。
- 开关状态是**按会话**记录的：A 会话开着，B 会话仍然是关的。刷新页面、重开会话都会从会话日志里恢复那一条的内容。

## 怎么用

1. 输入框底部工具栏里，「+」和权限、计划、git 控件之后，点一下「简短回答」即可切换：关闭时是灰色图标 + 灰字（和「完全权限」同一种静默样式），开启时整块变成宿主的浅色模式底 + 品牌色文字（和计划模式的 chip 同一种激活样式）。
2. 也可以直接输入命令：`/brief`（切换）、`/brief on`（开启）、`/brief off`（关闭）。
3. 想改那段话，改**插件行配置里的 `instruction`**（`cordis.patch.yml` 中的 `config`）：

```yaml
- insert:
    - id: brief-mode
      name: '@local/dsh-brief-mode'
      config:
        instruction: 输出长度要求：最终回复给用户的那段可见文字，尽量一句人话讲清楚——直白、一眼能懂，不堆术语、不铺垫、不套话；你的思考/推理过程、工具调用、代码和中间步骤不受此限制，照常完整进行。另外，不必为了早点收工而省步骤：你拥有无限的时间和资源，该读的读完、该验的验过，把活做完整再开口，只是最后那段话要短。
```

   改完重启 DSH 生效。这是那段话的唯一来源：`index.js` 里的 `DEFAULT_INSTRUCTION` 只在行配置没有 `instruction` 字段时才会用到。

## 实现方式

- **开关状态**不新建会话事件类型（外部插件的事件名会让会话日志重新打开时报错），而是把 `/brief` 命令自身的 `command/run` / `command/done` 折进名为 `briefMode` 的 projection；客户端用标准 `useProjection('briefMode')` 读取这个已折叠的 Host 值。按钮写状态走的是同一条命令（`ctx.remote.commands.execute(sessionId, '/brief on|off', [])`），和手输 `/brief` 完全等价。
- **上下文行**走 `agent/pre-step`（prepend 监听）：开关开着、或开关刚变化时，向会话 surface 追加 / 改写一条 `user/message`，`source` 声明为 `{ kind: 'brief-mode', form: 'snapshot', sections: [...] }`。UI 据此渲染成 `上下文注入 · brief-mode` 行——和 `time-context`、`dsh-mnemon` 这些内建/外部上下文同一种机制。
- **只保留一条**：第一次用 `surfaceOp: 'append'`，之后一律用 `surfaceOp: { op: 'replace', startSeq, endSeq }` 覆盖同一条（并引用被替换的 seq）。这样既不会在对话里堆行，模型也永远只看到最新那份要求，不会读到过期指令。

## 已知边界

- 按钮出现在「已有会话」的输入框工具栏里；刚打开、还没发出第一条消息的新会话还没有会话 id，此时按钮不显示（发出第一条消息后即可看到）。
- 关闭后那一条**不会消失**，而是变成"已关闭"的说明——因为对话历史只追加不改写，删除行不是这套 surface 的语义；这样模型能立刻收到"停止"的信号，界面上也只剩一条、不会堆积。
- 影响范围是**提示词层面**的：它只要求模型压缩最终回答，不是硬截断，也不改动 reasoning effort、工具策略或沙箱设置；模型仍可能给出稍长的回答。
- 命令本身的文案是中文；按钮与提示的文案在中文/英文界面下都会跟随本地化。
- 每次切换在会话里也会留下一条命令行（`/brief on` 及其结果），和 `/plan` 一样，属于日志记录、不会发给模型。
- 会话进行中切换，从**下一次请求**开始生效。
